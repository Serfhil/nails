# simulator.md — ТЗ симулятора

> **Паспорт роли — Симулятор.** Ты пишешь симулятор. Роль запускается только по прямой просьбе владельца.
>
> - **Пишешь только:** `simulator/`, `docs/simulator/`, `reports/simulator.md`.
> - **Читаешь:** этот документ целиком и `core.md` разд. 5–6 (API, вид, отладочный вид); `fixtures/mini-pack/` и `packs/*` как данные; движок — в порядке §2.1.
> - **Не трогаешь (не правишь):** `engine/`, `ui/`, `validator/`, `packs/`. В состояние движка напрямую не лезть.
> - Общие правила, зоны, чтение через граф, эскалация и формат отчёта — в `claude.md` (§0–§5, §9). Роль неясна из задачи — спроси владельца до любых действий.

> ## ⚠️ Делается только по отдельному запросу владельца. При первом запуске не строится.

**core.md приоритетен.** Если этот документ расходится с core.md, верен core.md; расхождение записывается в `CONTRACT_ISSUES.md`.

Порог «оптимизатор обязан выигрывать» в CI пока не задаётся. Тесты баланса не делаются: симулятор даёт цифры для глаза контентмейкера, а не проверку.

## 1. Назначение

1. Показать, как разные стили игры заканчивают забег (какие концовки, на какой день).
2. Измерить **скрытый контент**: какую долю забегов открывает каждая сущность. Это главный инструмент реиграбельности: контента должно быть больше, чем видно за один забег.

---

## 2. Что сдать

1. `/simulator` — TypeScript, Node ≥ 20.
2. Команда:
   `sim --pack <путь> --strategy <имя|all> --runs 1000 --cap 200 --seed-start 1 --out <папка>`
   `--trace <seed>` — один прогон с подробным пошаговым выводом.
3. md-описание в `/docs/simulator/`.
4. Отчёт `reports/simulator.md`.

Симулятор работает через `Game.perform`, `Game.view()` (решения стратегий — только по обычному виду, как у игрока) и `Game.debugView()` (только для сбора метрик: открытое и сработавшее). В состояние движка напрямую не лезет.

### 2.1 Как читать и подключать движок
Разрешено, в таком порядке (дальше идти, только если предыдущего не хватило):
1. `core.md` разд. 5–6 — команды, `View`, `debugView`.
2. `engine/src/index.ts` — публичный вход: `createGame(pack, seed)`, `loadGame`, экспортируемые типы. Читать сам файл и типы, на которые он ссылается (объявления типов, не реализацию).
3. `docs/engine/` — описания модулей; начать с `README.md` и `view-and-debug.md`, остальные — по необходимости.
4. Загрузка пака с диска — `loadPack(dir)` из `validator/src/index.ts` (только импорт; возвращает `{ pack, problems }`). Пак с ошибками (`problems` с кодом `V…`) не прогонять: вывести ошибки и выйти.
5. Если поведение движка непонятно по пп. 1–3 — точечно прочитать нужный файл `engine/src/` (только чтение, через граф), а вопрос записать в `CONTRACT_ISSUES.md`, чтобы Ядро дополнило `docs/engine/`.

Импортировать можно только `engine/src/index.ts` и `validator/src/index.ts`; внутренние модули движка и валидатора не импортировать. Ничего в `engine/` и `validator/` не править.

Команда в корне: `npm run sim -- …` вызывает `simulator/src/cli.ts`.

## 3. Стратегии

Код симулятора. Названия и порядок решений настраиваются подсказками пака `strategy_hints.json` (необязательный файл пака; валидатор проверяет ссылки, если файл есть).

| Стратегия | Поведение |
|---|---|
| `idle` | только спит |
| `routine` | сам работает самым дорогим доступным действием, продаёт, не нанимает |
| `solo` | как `routine`, плюс берёт заказы и отдыхает при стрессе |
| `delegator` | нанимает рано, учит, раздаёт поручения и торговлю |
| `random` | случайная доступная команда (полезен для покрытия) |
| `optimizer` | идёт к концовкам с `tag: "goal"` и избегает `tag: "fail"`: держит переменные из условий провальных концовок далеко от порогов, отвечает в окнах по подсказкам, сдаёт заказы, вкладывается в оборудование и апгрейд |

**Окна выбора.** Стратегия выбирает вариант по `strategy_hints.offer_choices` (`{ offer: option }`), иначе — первый доступный (для `random` — случайный).

**Подсказки** (пример формы, все поля необязательны):
```json
{ "action_ladder": ["forge_nails", "forge_horseshoes"], "hire_order": ["frol"],
  "buy_order": ["hammer_good"], "rest_action": "rest", "rest_when": { "var": "stress", "above": 60 },
  "offer_choices": { "ask_day_off": "yes" }, "traders": ["frol"] }
```
Если подсказок не хватает, стратегия работает на собственных значениях по умолчанию, выведенных из вида (самое дорогое по выходу доступное действие, отдых при `stress.warning`, первый доступный вариант окна и т. п.), без `id` пака в коде; в сводке помечается «без подсказок». Только если стратегия не может сделать ни шага — понятная ошибка и пропуск стратегии. Пороги и прочие числа по умолчанию симулятор выбирает сам и описывает в `docs/simulator/`.

## 4. Исходы прогона

Ровно один на прогон:
- `goal:<заголовок>` — `end_game` с `tag: "goal"`;
- `fail:<заголовок>` — `end_game` с `tag: "fail"`;
- `cap` — достигнут потолок дней без концовки.

Победа с продолжением: если стратегия выбрала «Продолжить», прогон идёт дальше, а факт достижения цели записывается.

---

## 5. Вывод

Только сводные таблицы, markdown и CSV в `--out`. Полных логов нет (кроме `--trace`).

**По стратегиям:** доли исходов; медианный день каждой концовки; медиана денег на 10/30/60/100/200-й день; доля прогонов с недееспособностью героя; число команд до концовки (медиана) — мера длины забега.

**Метрика закрытого (обязательная):** для каждой сущности с условием видимости или запуска (действие, переменная, модификатор, событие, предложение, вариант, концовка) — доля прогонов, в которых она открылась или сработала, по стратегиям и в сумме. Пометки:
- `< 1%` — **подозрительно** (возможно, недостижимо на практике);
- `> 90%` — **не скрытое** (видят почти все);
- пороги — настройки по умолчанию, пак может переопределить в `strategy_hints.coverage_thresholds`.

**Разброс** (необязательно, только если просто): средняя доля общих открытых сущностей у двух случайных забегов одной стратегии.
