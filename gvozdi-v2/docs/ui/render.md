# render.ts — рендер в HTML-строку

Назначение: `renderApp(view, ui, packs = []): string` — весь экран (`packs` — список паков сборки для окна «Настройки»). Чистая функция, проверяется в Node без браузера. Все строки вида экранируются (`esc`).

## Раскладка: шапка и три колонки
Шапка (п. 1) и сообщение (п. 2) — на всю ширину сверху. Под ними при ширине ≥ 900 px три колонки (`.cols` → `.col-left`, `.col-center`, `.col-right`); на узком экране одна колонка, порядок: центр, левая, правая.
- Левая: «Только что» (п. 4), «Сегодня» (п. 5), «Работники» (п. 8б), «Мастерская» (п. 9), «Семья» (п. 8), «Можно нанять» (п. 8а).
- Центральная: главные кнопки «Заняться делом» / «Спать до утра» (без заголовка, над «Делами»), «Дела» (п. 3), «Обстоятельства» (п. 13).
- Правая: «Заказы» (п. 6), «Доска объявлений» (п. 7), «Склад» (п. 10), «Рынок» (п. 11), «Общий инвентарь» (п. 12, бывшие «Вещи»).
Пустая колонка не рисуется.

## Порядок панелей (нумерация прежняя)
1. Шапка (липкая): `meta.game_title`, кнопка «Настройки» (`settings-open`, неактивна под другим окном; «Начать заново» в шапке нет); день и час, деньги, стресс (при `warning` — красный сургуч). Только сведения; содержимое одним блоком (`.top-in`) по центру, текст выровнен по левому краю.
2. Сообщение (ошибка команды и т. п.).
3. Дела — строка: слева кнопка с названием (все кнопки одной ширины), справа, по правому краю, поле цены (`.price-col`): время («N ч») и строки `cost` («название нужно»), красным те, где `have < need`. Причина отказа и «нужно / есть» подробно — во всплывающей подсказке строки. Выбор участников (списки по ролям) раскрывается под строкой. Описание действия (`ActionView.description`) — абзац `<p class="desc">` под кнопкой, не шире самой кнопки (колонка кнопки, цена справа не занята), мелким приглушённым шрифтом (видно без нажатия, удобно на телефоне); при `null` (или пустой строке) элемент не рисуется, места не занимает. Группировки по категории и описания эффекта нет — полей в виде нет (CI-023).
4. Только что — `stop.text` и `events` последней команды.
5. Сегодня — `notifications`, новые сверху; цвет по `kind`.
6. Заказы — `obligations`: срок, `requires`, «Сдать товар» (`can_deliver`), «Отказаться» (второе нажатие).
7. Доска объявлений — правая колонка, самая верхняя панель. Срок, текст, варианты как в окне выбора, без блокировки; кнопки вариантов стоят в ряд, если позволяет длина текста.
8. Карточка персонажа (одинаковая в «Работниках» и «Семье», панель `.family` — «Семья»: персонажи с `works: false`, `familyOf`) — имя, `role_name` (если не null), `blurb`, статус; под свёрнутыми блоками «Параметры» (`vars`: `name` и готовая `display`, ступень — друг под другом) и «Личный инвентарь» (слоты: `slot_name` и вещь с «Снять» или «пусто»; кнопка «Дать вещь» открывает список только из `equippable`, названия из `inventory`; как «Занятие», без поля выбора); строка «Занятие: текущее» с кнопкой «Новое» — по нажатию выпадает список `assignable`, выбор сразу уходит в `set_assignment`; строка «Мастерская: текущая» с кнопкой «Сменить» (при двух и больше), эффекты. Состояние свёртки — `ui.open` (ключи `p:<персонаж>:vars` и `p:<персонаж>:inv`), кнопка `data-act="fold"`.
8б. Работники — над мастерской (панель `.workers`, `workersOf`): все персонажи с `works: true`, в том числе герой (`role: "hero"`), герой первым, остальные в порядке вида (view.md 3.6, T-011). Карточка как в п. 8; «Занятие»/«Новое» — у всех, кроме героя (герой действует через «Дела», как и раньше). Разбиение только по `works`; пустой блок («Работники» или «Семья») не рисуется. У героя пометка «это вы». Исполнитель дела в «Делах» — всегда герой (если движок его допускает, иначе первый допустимый), выбора исполнителя нет; выбор партнёра/кандидата остаётся. Кнопка «Спать до утра» — на всю ширину блока.
8а. Можно нанять — `hire_pool`: имя, `role_name`, `blurb`, переменные, эффекты. Нанимают действием найма в «Делах» с выбором кандидата (имена из `hire_pool`).
9. Мастерская — вкладки (при двух и больше), переменные, оборудование, работники, эффекты. Переменная мест под оборудование (`equipment_slots`, зарезервирована core.md 4.3) показывается как квадратики и подпись «занято N, свободно M»; занято — число записей `equipment`.
10. Склад — «название: количество единица», одна подпись-заголовок «Продать на рынке» над колонкой галочек (у самих галочек подписи нет, только `aria-label`), внизу «Всего на продажу:» — оценка по отмеченным товарам (`saleValue`), а не `total_value`. Больше шести товаров — список с прокруткой (`.stock.scroll`, полоса в стиле темы). Строки компактные (≈ 34 px).
11. Рынок — кнопка похода (часы); активна, если `enabled` и лавка не дороже денег плюс выручки от отмеченных к продаже товаров (иначе подсказка «Не хватает: N»). Закупка сырья — у каждого два поля: «Купить» и «Поддерживать количество» (по умолчанию 10, запоминается, хранится в `ui`-сохранении). Если «Купить» пусто, покупается разница между «Поддерживать» и остатком на складе; введённое «Купить» главнее; расчёт виден в подсказке поля (placeholder). Сырьё покупается по списку, пока хватает денег (деньги + выручка − лавка), при нехватке в панели предупреждение. Лавка: причина недоступности только подсказкой. Раскрытия описаний предметов лавки нет (CI-021).
12. Вещи — `inventory` с эффектами.
13. Обстоятельства — `effects`; `negative` — тёмная плашка; `numbers` — если не null; срок.

## Подсказки на телефоне (T-012)
Подсказка `title` на сенсорном экране не появляется. Поэтому там, где причина отказа выводится только подсказкой (недоступное дело, предмет лавки, нехватка денег у кнопки рынка), рядом рисуется её текстовая копия `<div class="tip-touch">`. В CSS она видна при ширине < 900 px и скрыта на устройствах с мышью (`hover: hover` и `pointer: fine`), так что на десктопе всё остаётся подсказкой. У выбранного дела в группе `select` копии нет: причина там уже выведена строкой `.reason`.

## Выпадающие списки
`dropdown()` рисует кнопку `data-act="dd"` (текущее значение) и список вариантов — кнопки с исходным `data-act` (`pick`, `equip`, `assign`, `assign-ws`), данными поля и `data-value`. Закрытый список остаётся в разметке с `hidden`. Любое другое нажатие закрывает список (`app.ts`: `dd-close`). Недоступный вариант — серый, с причиной в подписи.

## Главные кнопки
ВРЕМЕННО: «Заняться делом» закомментирована в `mainButtonsHtml` по просьбе владельца; остаётся «Спать до утра». Логика `work` в `app.ts` и `model.ts` не тронута.

## Окна
- Окно выбора (`pending_offer`): заголовок, текст, варианты; недоступный — серый с `reason` и `cost`. Под окном `main` получает `inert`, все кнопки и поля — `disabled`.
- Окно замены оборудования (`ui.replacing`, у действия `replace` не null): заголовок — подпись действия, текст — `replace.warning`, кнопки по `replace.options` (`name`) и «Не менять». Блокирует всё, как окно выбора.
- Итог дня: крупный заголовок; под ним количество монет (`money_morning`) и сразу под ним изменение за день (`delta`, со знаком, без подписи: зелёным при плюсе, красным при минусе); ниже две строки «Доходы» и «Расходы» — «N за день, всего M» (за день — сумма строк `income` / `expense`, всего — накопленная интерфейсом по итогам дней, `ui.totals`); кнопка «Подробнее» / «Скрыть» раскрывает строки `income` и `expense`. Строки `morning` не выводятся; кнопка «Понятно».
- Концовка: вместо всего экрана — метка исхода, `title`, `text`, только «Начать заново».

## Разметка событий
Каждый активный элемент несёт `data-act` и данные: `work`, `sleep`, `restart`, `settings-open`, `settings-close`, `action` (id), `pick` (role), `pick-go`, `pick-cancel`, `choose` (offer, option), `deliver` (id), `decline` (id), `assign` (char; value — индекс в `assignable`), `assign-ws` (char; value — id мастерской), `equip` (char; value — экземпляр), `unequip` (char, item), `sell-flag` (id), `market-raw` (id), `market-item` (id), `market-go`, `ws-tab` (id), `replace-choose` (item), `replace-cancel`, `summary-details`, `summary-close`.

## Группы действий (view.md 3.2)
`groupActions(view)` (model.ts) делит разовые действия: без `category` (или с неизвестной) идут списком вне групп, затем группы в порядке `view.categories`; категория без действий не рисуется. Заголовок группы: `name (N)`, N — число действий с `enabled`.
- `list` — кнопка-заголовок `data-act="cat-fold"` (`data-id`), по умолчанию свёрнута; раскрытых может быть несколько.
- `select` — выпадающий список `cat-pick` (`data-cat`, `data-value` = id действия). Недоступные пункты видны с причиной в подписи и не выбираются. Под списком — обычная плашка выбранного действия (описание, расход, кнопка выполнения), для недоступного — ещё `reason`.
Состояние: `UiState.catOpen` (раскрытые id категорий) и `UiState.catPick` (категория → действие); хранится в интерфейсе, переживает перерисовку после команды, в `localStorage` не пишется. Выбор, которого уже нет в виде, молча игнорируется.
Панель `workshop` теперь имеет CSS-класс `wshop` (слово `workshop` совпало с id в паке и ломало проверку чистоты).

## Окно «Настройки» (view.md 3.14)
`settingsModal`: фон `.overlay` с `data-backdrop="settings-close"` (тап мимо), заголовок «Настройки» и крестик `×` (`settings-close`, 48×48, `aria-label`); блок `.about` — `meta.game_title`, «версия `meta.pack_version`», `meta.pack_description` (при `null` не рисуется); «Начать заново» (второе нажатие — `restartConfirm`, `.armed`); «Выбор пака» — `ul.pack-list` из `packsForView`: текущий (`id === meta.pack_id`) — `li.pack.current` с меткой «Открыт сейчас» и `aria-current="page"`, без ссылки; другие — `a.pack-link href=url` (название, версия, описание). Игра под окном `inert`.
