# packs.ts — список паков сборки (окно «Настройки»)

Назначение: список паков для «Выбора пака» (view.md 3.14). Движок его не отдаёт: список кладёт в страницу сборка (`ui/build.ts`) в `<script type="application/json" id="pack-list">`, `main.ts` разбирает его и передаёт в `createApp({ packs })`.

## Поля `PackEntry`
| Поле | Откуда | Смысл |
|---|---|---|
| `id` | `pack.json` `id` | по нему отмечается текущий пак (`=== view.meta.pack_id`) |
| `name` | `pack.json` `name` | название в списке |
| `version` | `pack.json` `version` | «версия …» |
| `description` | `pack.json` `description` или `null` | описание; `null` или пустая строка — не рисуется |
| `url` | сборка | относительная ссылка на страницу пака **от текущей страницы** |

## Правила
- `parsePackList(text)` — не JSON или не массив дают `[]`; записи без строковых `id`/`url` отбрасываются.
- `packsForView(view, list)` — если в списке нет текущего пака (обычная сборка без списка, тесты), он добавляется первым по `view.meta` (`game_title`, `pack_version`, `pack_description`). Пак один — в окне всё равно один пункт.
- Текущий пак рисуется отмеченным («Открыт сейчас», `aria-current="page"`) и без ссылки. Остальные — обычные ссылки `<a href>`: переход делает браузер, интерфейс при этом ничего не пишет в хранилище.
- Сохранение у каждого пака своё (`gvozdi-v2:<pack.id>:save`, `…:ui`, см. storage.md). Переход и «Начать заново» трогают только ключи текущего пака.

## Пример (страница `dist/packs/b/index.html`, основной пак `a`)
```json
[
  { "id": "a", "name": "Пак А", "version": "1.0.0", "description": "…", "url": "../../index.html" },
  { "id": "b", "name": "Пак Б", "version": "0.2.0", "description": null, "url": "index.html" }
]
```
