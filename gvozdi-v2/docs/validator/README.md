# Валидатор пака

Контракт: core.md 2.1.

Проверяет пак (папку JSON-файлов по разделу 4 core.md) **как данные**, без кода движка. Находит ошибки, из-за которых пак не принимается (V001–V014), и предупреждения (W001–W010). Контентмейкер запускает его после каждого блока пака; сборка и тесты зовут его как библиотеку.

## Запуск

```
npm run validate -- <путь к паку>          # текст, по строке на проблему, сначала ошибки
npm run validate -- <путь к паку> --json   # массив объектов Problem
npm run test:validator                     # тесты валидатора
npm run make-broken                        # пересоздать fixtures/broken/*
```

Код выхода: `0` — ошибок нет (предупреждения допустимы), `1` — есть хотя бы одна ошибка, `2` — не указан путь.

## Библиотека (`validator/src/index.ts`)

| Функция | Что делает |
|---|---|
| `loadPack(dir): { pack, problems }` | читает файлы пака (fs), разбирает JSON и проверяет. `pack` — объект по CI-001: `{ pack, variables, …, strategy_hints? }`, значения — JSON как есть; битый или отсутствующий файл — ключа нет |
| `validatePack(pack): Problem[]` | проверяет уже загруженный объект; **не зависит от fs** |
| `formatProblems(list)` / `formatProblem(p)` | текстовый вывод |
| `hasErrors(list)` | есть ли `error` |

```ts
interface Problem { severity: "error" | "warning"; code: string; file: string; id: string; path: string; message: string }
```
`id` — id записи (для `pack.json` — id пака, для `texts.json` — ключ, для файла целиком — `-`); `path` — поле внутри записи (`cost[0].good`, `options[1].obligation.requires`), пусто — запись целиком.

Формат строки: `<severity> <code> <file> <id> <path> — <сообщение>`:
```
error V003 actions.json make_widget cost[0].good — товар «oer» не объявлен в goods.json. Возможно, имелось в виду «ore».
```

## Правила, принятые валидатором

- Категории действий (T-006, core.md 4.9, 4.9.1): `categories.json` — необязательный файл (массив `{id, name, view?}`, `view` ∈ `list`/`select`; V001 на схему, V002 на дубликаты `id`, W010 на неизвестное поле, на сам файл W010 не даётся). `category` у действия — необязательный `id` или `null`; несуществующая категория — V003 с подсказкой «возможно, имелось в виду» (если файла нет вовсе, любая `category` — V003). Категория, которой не пользуется ни одно действие, — W002 (на неполном паке не проверяется). Нет файла и нет поля — ни ошибок, ни предупреждений. Фикстуры: `V001_category_view`, `V001_category_no_name`, `V002_duplicate_category`, `V003_unknown_category`, `V003_category_no_file`, `W002_empty_category`.

- Поля `pack.json` (T-015, core.md 4.2): `name`, `version` — обязательные непустые строки; строка из одних пробелов считается пустой. Примеры: `error V001 pack.json base version — строка не может быть пустой.`, `error V001 pack.json base version — нет обязательного поля «version».`, `error V001 pack.json base description — ожидалась строка, получено 42.` `description` — необязательная строка или `null`; отсутствие — ни ошибки, ни предупреждения, W010 на него нет. Пустая строка в `description` допускается (контракт её не запрещает). Фикстуры: `V001_pack_empty_version`, `V001_pack_description_type`.

- `null` в необязательном поле = «не задано». Условия видимости/открытия принимают `null`, `true`, `false` и дерево условий.
- Поля контракта 2.1: `names.slots` (обязателен для используемых слотов), `names.roles` {hero, worker, family, pet}, `role_name` у персонажа, `kind` у `notify`, `transfer` {equipment, workers, modifiers, overflow}. Сверх core.md допускаются `data_defaults` и `visible` у событий и предложений.
- Обязательны (core.md не помечает, но без них не построить вид): `name` у товаров, предметов, мастерских, персонажей, действий, модификаторов (кроме `visible: false`); `title` у предложений и обязательств; `label` у вариантов; `title`, `text` у `end_game`; `slot` у инструментов. `target` у эффектов не обязателен (движок подставляет значение по умолчанию).
- Если какого-то файла нет или он не разобран, ссылки на его сущности не проверяются (нет каскада V003), а проверки «по всему паку» (V010, W001, W002, W003, W009) не выполняются — сначала нужен полный пак.
- Срок модификатора не задан → считается вечным (для V009). Модификаторы из `characters[].modifiers`, предметов, мастерских и ступеней — `source` (снимаются вместе с источником).
- `visible: false` у переменной — сознательно скрыта навсегда, V010 не даёт (CI-004).
- `run_event` запускает событие без проверки `trigger.conditions` (CI-007).

## Алгоритмы

### Достижимость (V010)
Оптимистичная неподвижная точка, без денег, вероятностей и времени.

Факты: товары, предметы, мастерские, персонажи (в игре / в пуле / наняты), шаблоны модификаторов и их теги, ступени лестниц, сработавшие события, показанные предложения, выбранные варианты, обязательства (создано / сдано / провалено / отклонено), открытые действия; по переменным — «может расти», «может падать», заданные `set` значения.

Старт: герой `start.hero`; персонажи с `hire_pool: true` в пуле; товары с `buy: true` (рынок); деньги могут и расти, и падать.

Шаг (повторяется, пока что-то меняется):
- условие выполнимо, если выполним каждый лист: `not`, сравнения `<`, `<=`, `!=`, а также `day`, `hour`, `calc`, `role`, `self_is_hero`, `var_cmp`, `data` — всегда; `var` с `>=`/`>`/`==` — если до значения можно дойти (стартовые значения, `set`, рост от эффектов, `per_hour`, модификаторов значения; не выше `max`); `field: "level"` — если достижима нужная ступень; `has_modifier` — шаблон (тег) наложен (`min_count` > 1 — только при `stack: true`); `has_item`, `stock`, `hired`, `worker_count`, `workshop_type`, `obligation`, `event_count`, `incapacitated` — по фактам; субъект не учитывается;
- сигнал испускается, если есть достижимый повод: `game_start`, `night`, `morning`, `market_trip` — всегда; `action_done` — есть открытое действие; `batch_defect` — с выходами; `idle_no_cost` — поручение с расходом; `ladder_step` — у лестницы достижимы ≥ 2 ступени; `modifier_expired` — модификатор со сроком `days`; `became_visible` — в паке есть условия видимости; `incapacitated` — модификатор `incapacitates` или `floor_pct`; `hired`; `obligation_*`; `offer_expired` — показана запись доски;
- действие открыто, если выполнимы `open_when`, `enabled_when`, расход и роли (`worker` — есть работник, `pool` — пул не пуст) → его выходы, `per_hour`, эффекты;
- событие срабатывает по сигналу/условию (и участнику: `among: workers` — есть работник, `family` — есть семья) или по достижимому `run_event` → эффекты;
- у показанного предложения выбирается каждый вариант с выполнимыми условиями и ценой → эффекты; обязательство создаётся и даёт `on_decline`, `on_fail` (если есть `deadline_days`), `on_done` (если `requires` набирается);
- наложенный модификатор даёт `on_expire`; предметы, мастерские, персонажи и ступени дают свои модификаторы; найм `candidate` нанимает всех, кто попадает в пул; `give_item` оборудования в мастерскую считается дающим предмет (правила мест 3.7 не учитываются — оптимистично).

Всё, что не попало в факты, — V010 с причиной (какой узел условия невыполним). Сущность, которая вовсе не используется, получает W002, а не V010.

### Видимый предвестник (W003)
Для каждого `end_game` с `tag: "fail"` собираются переменные и модификаторы из условий запуска: условия события (`trigger.conditions`, `participant.where`); для события без `trigger` — условия всех, кто его вызывает (`run_event`); для варианта — его `open_when`/`enabled_when` и условия событий, которые показывают предложение; для `on_expire` — сам модификатор. Лист `data` со значением, равным id переменной или модификатора (например, `ladder_step` по `stress`), тоже считается ссылкой.

Предвестник есть, если: переменная видима (нет `visible` или оно достижимо истинно); модификатор не `visible: false`; есть другое достижимое событие с `notify`/`show_offer`, чьи условия ссылаются на ту же переменную или модификатор. Видимыми считаются и деньги/склад/статус/заказы — условия `calc`, `stock`, `incapacitated`, `obligation`, а также концовки из действия игрока или ветки обязательства.

### Данные (V006, W004)
Для каждого события, предложения, обязательства и модификатора считаются имена данных: «возможные» (объединение по всем источникам) и «гарантированные» (пересечение). Источники: данные сигнала (core.md 3.9), `data` эффекта `run_event`/`show_offer`/`add_modifier`, данные вызвавшего события, `data` предложения и обязательства; плюс `data_defaults`. `{participant}` доступен, если у события есть `participant`, `run_event` передаёт участника или его даёт вызвавшее событие. Подстановку, которой нет нигде, — V006; есть не у всех источников — W004. Любой `{"$data": …}` в эффектах, условиях, расходе, сроках без гарантии — W004.

### Циклы (V008)
Граф: событие → событие (`run_event`, если у цели нет `repeat.max`/`cooldown_days`), событие → предложение (`show_offer`), предложение → цель (если **все** варианты ведут к ней), событие/модификатор → модификатор (`add_modifier` со сроком `days` и `on_expire`), модификатор → цели `on_expire`. Сильно связная компонента с циклом — V008.

### Негатив (V009)
Негативный — `incapacitates` или ухудшает переменную с учётом `good` (`up` по умолчанию): для значения — знак `add`/`pct`, `mult` < 1; для изменений — `gain`-усиление/`loss`-ослабление и наоборот. Вечный — `forever`, без срока, или `while` с условием, которое не может стать ложным (`day >=`, `event_count >=`, обязательство в конечном состоянии). Ошибка, если такой модификатор накладывается эффектом, не снимается ни одним `remove_modifier` (по шаблону или тегу) и нет `may_be_permanent`.
