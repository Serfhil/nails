# Найм, персонажи, мастерские, предметы (`workforce.ts`)

**Назначение.** Ввод персонажей в игру, пул найма, мастерские, экземпляры предметов, апгрейд.

## Персонажи
- Герой создаётся из `start.hero` до всего остального. Персонаж в игре имеет `id` шаблона; повторный ввод того же шаблона — без эффекта.
- Вид персонажа (`kind`): `hero`, `worker` (нанят или `add_character as: worker`), `family`, прочие (роль шаблона, например `pet`). Условие `role` и `CharacterView.role` берут его.
- `works: false` — не получает назначений (у `family` назначения только при явном `works: true`).
- Модификаторы шаблона накладываются при вводе в игру.

## Пул найма
Начально — шаблоны с `hire_pool: true`; `add_to_hire_pool` добавляет. Кандидаты — в `view.hire_pool` (`CandidateView`: id, имя, `role_name`, описание, видимые переменные, видимые модификаторы шаблона) и в `ActionView.roles.candidate`; в `view.characters` их нет. Условие `role` у кандидата берёт роль шаблона.

## Найм (`hire`)
Только из пула и пока нанятых меньше Σ`max_workers` всех мастерских. Нанятый уходит из пула, при одной мастерской приписывается к ней (иначе — `assign_workshop`), строка `log_hired`, сигнал `hired {character}`. Действие с эффектом `hire` при нехватке мест — серое (`reason_workers_full`).

## Мастерские
Экземпляры `ws<N>`. Переменные `max_workers`, `equipment_slots`, `upkeep` и прочие `owner: "workshop"`. `assign_workshop` проверяет место в конкретной мастерской. Утренние расходы — `upkeep` каждой мастерской.

## Предметы
Экземпляры `it<N>` с переменными `owner: "item"`. Инструменты (`kind: tool`) лежат в инвентаре героя или в слоте персонажа, оборудование (`kind: equipment`) — в мастерской. `equip`/`unequip` работают только с инструментами: перекладывают между инвентарём и слотом; если слот занят, прежний предмет уходит в инвентарь. В `CharacterView.equippable` — инструменты из инвентаря, чей `slot` есть у персонажа. `slots[].slot_name` берётся из `names.slots`. Подпись роли `role_name` — поле шаблона, иначе `names.roles[роль]`, иначе `null`.

## Оборудование
Модуль `equipment.ts`. Места в мастерской обезличены (`equipment_slots`). У оборудования есть линейка `line` и уровень `grade`: без `line` линейкой считается id типа, без `grade` уровень равен 1. Установка X в мастерскую M (`placement`):
1. `blocked` — у M 0 мест или уже стоит та же линейка с уровнем ≥ X;
2. `upgrade` — стоит та же линейка ниже уровнем (если таких несколько, берётся самая низкая): она исчезает, X встаёт на её место;
3. `free` — есть свободное место;
4. `replace` — все места заняты другими линейками.

Заменённое оборудование уничтожается вместе со своими модификаторами. Ручной установки и снятия нет. В инвентарь оборудование не попадает — кроме `overflow: "inventory"` при апгрейде мастерской.

**Действие, ставящее оборудование** — в его `effects` есть `give_item` оборудования с целью `workshop`; мастерская — мастерская исполнителя.
- Случай 1: действия для игрока нет (проверка входит в `actionOpen`, как ложный `open_when`); команда даёт `not_available`.
- Случай 4: у `ActionView` есть `replace: { warning, options }`. `warning` — `texts.replace_warning {item, old}`, где `old` — названия стоящего оборудования через запятую; `options` — экземпляры на выбор. `do_action` без `replace` даёт `requirement_unmet` с текстом предупреждения, с чужим id — `invalid`. Выбор передаётся в эффект `give_item`.

**Оборудование из событий и предложений** (выбора нет): случаи 2 и 3 — как выше. В случаях 1 и 4 предмет не выдаётся, в `debugView().errors` пишется «оборудование … не выдано». `give_item` оборудования с целью-персонажем ставит его в мастерскую этого персонажа.

## Апгрейд (`replace_workshop`)
Новый экземпляр другого типа встаёт на место старого. `transfer` (CI-005): `{ equipment?: true, workers?: true, modifiers?: true, overflow?: "destroy"|"inventory" }`. Переезжают: модификаторы, наложенные эффектами; работники; оборудование по порядку установки, пока есть слоты; лишнее — уничтожается или в инвентарь. Переменные — из шаблона нового типа. Модификаторы типа (`modifiers` шаблона) — нового типа.

## Пример
```json
{ "type": "replace_workshop", "target": "workshop", "workshop": "bakery", "transfer": { "overflow": "inventory" } }
```
