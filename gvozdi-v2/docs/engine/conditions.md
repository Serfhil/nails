# Условия (`conditions.ts`)

**Назначение.** Проверка дерева условий пака; причина отказа для игрока; трассировка каждого узла для отладочного вида.

## Форма
- `null`, `undefined`, `true` — истинно; `false` — ложно; массив — «все».
- `{"all":[…]}`, `{"any":[…]}`, `{"not":…}`, листья `{"type":…}`. У любого узла может быть `text`.

## Субъекты
`hero`, `self`, `actor`, `partner`, `candidate`, `participant`, `world`, `workshop`, `char:<id>` (персонаж в игре). `workshop` — мастерская первого заданного из `actor`, `participant`, `self`, иначе героя: своя приписка, у героя и неприписанных — первая мастерская игрока. Кандидат из пула найма читается по своему шаблону (только чтение).

Контексты: видимость действия — `self = actor = герой`; доступность — `self = actor = исполнитель`; роль `where` — `self` = проверяемый персонаж; условия события — данные сигнала и участник (`self = participant`); видимость переменной/модификатора — `self` = владелец; предложение — `participant` и `self` = участник (иначе герой).

## Листья
| type | Истинно, когда |
|---|---|
| `var` | итог (`field: "level"` — уровень лестницы) сравнение `value` |
| `var_cmp` | то же для субъектов `a` и `b` |
| `has_modifier` | копий шаблона `template` (или с тегом `tag`) ≥ `min_count` (1) — учитываются и модификаторы от источников |
| `has_item` | экземпляр типа в слоте персонажа (у героя — и в инвентаре); у мастерской — оборудование; у мира — где угодно |
| `stock`, `day`, `hour`, `calc` | склад, календарь, расчётная величина (`action` — для `cost_hours`) |
| `role` | роль персонажа: `hero`, `worker` (нанят или добавлен работником), `family`, иначе роль шаблона |
| `self_is_hero`, `hired`, `worker_count`, `workshop_type`, `incapacitated` (`permanent`), `obligation` (по `id` шаблона обязательства и `state`), `event_count`, `some` (`among`, `where` с `self` = каждый), `data` | как в core.md 4.12 |

Операторы: `>=`, `>`, `<=`, `<`, `==`, `!=` (числа сравниваются с допуском 1e-9). `value` может быть `{"$data": "имя"}`. Нет субъекта или его сущности — лист ложен. Неизвестный тип — ложь и запись в ошибки.

## Причина
`failText`: сверху вниз первый ложный узел с `text`. Если такого нет — `disabled_text` действия/варианта, иначе `texts.reason_not_available`.

## Пример
```json
{ "type": "var_cmp", "a": "partner", "b": "actor", "var": "bake_xp", "field": "level", "op": ">",
  "text": "Учитель должен быть искуснее ученика." }
```
