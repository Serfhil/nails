# Переменные и лестницы (`vars.ts`)

**Назначение.** Хранит сырые значения переменных сущностей и считает итоговые; проводит изменения через модификаторы изменений; определяет ступень лестницы.

## Поля переменной (variables.json)
`id`, `name`, `owner` (`character`/`workshop`/`item`/`world`), `start`, `min`, `max?`, `format?` (`number`/`pct`/`money`, по умолчанию `number`; `pct` хранится долей, строку `display` делает движок — см. view-and-debug.md), `floor_pct?`, `good?` (`up`/`down`), `ladder?`, `visible?`.

У каждой сущности типа `owner` есть все переменные этого типа. Начальное сырое значение — `start`, шаблон сущности (`vars` персонажа, мастерской, предмета) может переопределить. Если пак не объявил `money` или `stress`, действуют умолчания core.md 4.3.

## Правила
- **Итог:** `(сырое + Σadd) × (1 + Σpct/100) × Πmult`, затем `min`/`max`. Учитываются модификаторы с `applies_to: "value"` на эту переменную этой сущности (хранимые и от источников).
- **Изменение на d** (эффект `var` с `add`, начисление за час, утренние расходы): `d' = (d + Σadd) × (1 + Σpct/100) × Πmult` по модификаторам `applies_to: "change"` с подходящим `direction` (`gain` при d>0, `loss` при d<0, `any`); если знак `d'` противоположен знаку `d`, `d' = 0`; затем `сырое += d'` в пределах `min`/`max`.
- `set` в эффекте `var` ставит сырое значение напрямую (без модификаторов изменений).
- **Расход и цены** списываются ровно, мимо модификаторов изменений (`addExact`).
- **`action_tags`:** модификатор действует, только пока владелец выполняет действие с пересекающимися тегами — разовое (на время его часов) или назначенное (пока назначение стоит).
- **Цикл в данных** (итог зависит от себя через `value_from` или лестницу) не зацикливает движок: на повторном входе берётся значение без модификаторов лестниц / сырое.

## Лестница
- Ступени сортируются по `at`. Текущая ступень — последняя с `at ≤ итог`; её номер — уровень (`field: "level"` в условиях).
- Модификаторы ступени действуют на владельца (или `target: hero/world`), только пока ступень текущая.
- Переход даёт сигнал `ladder_step` на **каждую** пройденную ступень: `{ var, owner, step, level, dir: "up"|"down" }`; `owner` — `id` сущности (`world` для мира). При появлении сущности её уровень запоминается без сигнала.

## Пример
```json
{ "id": "bake_xp", "owner": "character", "start": 0, "min": 0,
  "ladder": [ { "at": 0, "id": "novice", "name": "Новичок", "modifiers": ["clumsy"] },
              { "at": 10, "id": "apprentice", "name": "Подмастерье", "modifiers": ["wage_apprentice"] } ] }
```
При опыте 10 «Неумеха» снимается, «Ставка подмастерья» действует, сигнал `ladder_step` с `step: "apprentice", level: 1, dir: "up"`.

## Нормализация чисел (`norm` в `engine.ts`)
Чтобы не было шума плавающей точки (`74.00000000000003`), движок округляет число до 9 знаков после запятой (при |x| ≥ 10⁶ — до 3), а −0 превращает в 0. Это делается везде одинаково: при записи сырого значения, в итоговом значении, в величине `value_from`, в фактическом изменении и движении денег, в количестве на складе, в ценах рынка, в расчётных величинах, в суммах итога дня. Поэтому условия, сохранение и вид видят одни и те же чистые числа. Детерминизм и save/load это не меняет. В готовых строках (подстановки `{…}`, `numbers` у эффектов) числа ещё и форматируются до 2 знаков.
