# Симулятор

**Назначение** (simulator.md §1): прогнать много забегов разными стилями игры и показать, чем они кончаются, и какую долю забегов открывает каждая сущность пака (скрытый контент). Цифры — для глаза контентмейкера, не проверка.

## Запуск

```
npm run sim -- --pack <путь> [--strategy <имя|имя,имя|all>] [--runs 1000] [--cap 200] [--seed-start 1] [--out <папка>] [--jobs N]
npm run sim -- --pack <путь> --strategy <имя> --trace <seed> [--cap 200]
```

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `--pack` | — | папка пака; грузится `loadPack` валидатора. Есть ошибки `V…` — вывод ошибок, выход с кодом 1 |
| `--strategy` | `all` | `idle`, `routine`, `solo`, `delegator`, `random`, `optimizer`, список через запятую или `all` |
| `--runs` | 1000 | прогонов на стратегию; зёрна `seed-start … seed-start+runs−1` |
| `--cap` | 200 | потолок дней: день > cap → исход `cap` |
| `--out` | `sim-out` | папка сводок |
| `--jobs` | число ядер − 1 | потоков (`worker_threads`); `0` — всё в одном процессе (медленнее, для отладки) |
| `--trace <seed>` | — | один прогон с пошаговым выводом в консоль; воспроизводим (одно зерно — тот же вывод) |

Пример: `npm run sim -- --pack fixtures/mini-pack --strategy all --runs 100 --cap 100 --out sim-out`.

Тесты: `npx tsx --test "simulator/test/**/*.test.ts"`. Проверка типов: `npx tsc --noEmit -p simulator/tsconfig.json` (корневой `tsconfig.json` папку `simulator/` пока не включает).

## Модули

| Файл | Что делает |
|---|---|
| `src/cli.ts` | разбор флагов, запись сводок |
| `src/index.ts` | `load`, `simulate` (пул потоков), `traceRun` |
| `src/worker.ts` | поток: пачки по 10 зёрен. Перед запуском поток собирается esbuild в один `.mjs` во временной папке (под tsx код ~30% медленнее); если сборка не вышла — запускается `worker.ts` |
| `src/run.ts` | один прогон: стратегия ↔ `Game.perform`, исход, метрики |
| `src/strategies.ts` | стратегии и числа по умолчанию (`DEFAULTS`) |
| `src/hints.ts` | чтение `strategy_hints.json` и статический разбор пака по полям контракта |
| `src/coverage.ts` | перечень сущностей с условием и сбор открытого |
| `src/report.ts` | сводки markdown и CSV |
| `src/rng.ts` | генератор стратегий (mulberry32), зерно — зерно прогона |

В коде нет `id`, названий и текстов пака (тест `simulator/test/sim.test.ts` ищет `id` мини-фикстуры в исходниках). Из пака читаются только поля контракта: `end_game`, `open_when`, `visible`, `outputs`, `cost`, `item`, `trigger`.

## Как прогон говорит с движком

- Решения стратегий — по `game.view()` (результат `perform`).
- `debugView()` — для метрик и в двух местах для решений (оговорено ниже). Он дорогой, поэтому снимается не после каждой команды, а в контрольных точках: после сна, на закате, после выбора в окне, при появлении окна или изменении доски, в конце прогона.
- Ошибка команды: запасной ход — первый доступный вариант окна, иначе «работать до остановки» (ночью — спать), иначе спать. Если и это не прошло — стратегия пропускается с понятной ошибкой.
- Предохранитель: больше `cap × 300` команд за прогон — ошибка «стратегия зациклилась», стратегия пропускается.

Оговорки о данных для решений:
1. **Шаблон предложения.** В `OfferView` нет id шаблона, а `offer_choices` в подсказках задан по шаблону. Шаблон берётся из `debugView().offers` по id экземпляра (CI-028).
2. **Статический разбор пака** («книга рецептов»; не состояние движка): какой вариант окна ведёт к концовке `goal`/`fail`; условия на переменные у событий с провальной концовкой; какое действие выдаёт какой товар (`outputs`) и какой предмет (`item` в эффектах). Используется optimizer'ом и (для полуфабрикатов) всеми рабочими стратегиями.

## Стратегии

Общий «бот» (routine, solo, delegator, optimizer) за один шаг делает первое подходящее:
1. окно «сейчас» — вариант (см. «Окна»);
2. сдать обязательство, которое можно сдать;
3. ночь — спать;
4. галочки продажи: продаётся всё, кроме сырья рынка и товаров, которые идут в расход открытых действий (полуфабрикаты);
5. (solo+) взять предложения с доски — вариант как в окне, каждую запись один раз;
6. (solo+) отдых, если устал (см. ниже);
7. (delegator, optimizer) найм: разовое действие с ролью `candidate`, кандидат — первый по `hire_order`, иначе первый в пуле; не тратит ниже запаса денег; не больше `maxHires…`;
8. (delegator, optimizer) обучение: разовое действие с ролью `partner`, исполнитель которого — не герой (ученик); раз в день;
9. (delegator, optimizer) поручения: работникам — лучшее производственное действие; при двух и больше работниках последний (или указанный в `traders`) — торговец;
10. (optimizer) вложения: разовые действия, стоящие только денег, по `buy_order` (предмет или действие; действие покупки получает место своего предмета), иначе от дешёвых; каждое — один раз за забег; замена оборудования — только если оно в `buy_order`; не ниже запаса денег;
11. рынок раз в день (и ещё раз, если сырьё кончилось): продать отмеченное, купить сырьё под лучшее действие на остаток дня × число производящих; optimizer докупает предметы лавки из `buy_order`;
12. назначить герою лучшее производственное действие;
13. «работать до остановки».

**Лучшее производственное действие** — из поручаемых персонажу (`assignable`, разрешённых): место в `action_ladder` (выше — лучше), без подсказок — сумма «нужно» в строках расхода (дороже вход — дороже выход), при равенстве — позже в списке действий. Годится, если весь недостающий расход — сырьё рынка. Если лучшее упирается в полуфабрикат, берётся доступное действие, которое этот товар производит (CI-027). Действие, на котором герой встал (расход кончился), до утра не выбирается.

**Отдых.** Действие отдыха — `rest_action` из подсказок, иначе разовое действие без расхода и без ролей `partner`/`candidate`, после которого усталость (`view.stress`) упала (стратегия пробует по очереди и запоминает). Когда отдыхать: `rest_when` из подсказок; без них — `stress.warning`; всегда — если `stress` персонажа ≥ 60% максимума или если утренняя усталость + вчерашний прирост за день ≥ 90% максимума; optimizer — ещё при 70% порога переменной из условия провальной концовки. Не больше 4 отдыхов в день на персонажа. Работники отдыхают, только если их `stress` виден в виде и действие отдыха уже известно.

| Стратегия | Что включено |
|---|---|
| `idle` | только спит; в окне — первый доступный вариант (или по подсказке) |
| `routine` | п. 1–4, 11–13 |
| `solo` | + доска и отдых |
| `delegator` | + найм (до 3), обучение, поручения и торговля |
| `random` | случайная команда: в окне — случайный вариант; с вероятностью 0,3 — команда без времени (сдать, взять с доски, назначение, надеть, галочка), не больше 5 подряд; днём с вероятностью 0,05 — сон, 0,5 — случайное доступное разовое действие или поход на рынок со случайной закупкой (0–10 каждого сырья), иначе «работать» |
| `optimizer` | всё из delegator (найм до 2) + вложения, запас денег, выбор вариантов к `goal` и мимо `fail` |

**Окна.** Вариант, ведущий к `end_game` с `tag: "goal"` (только optimizer) → вариант из `offer_choices` → (optimizer) первый вариант, не ведущий к `fail` → первый доступный.

**Запас денег** (optimizer, delegator при найме): 20, а если у провальной концовки есть условие `money <= X` — `X + 20`. На закупку сырья запас не действует; выручка на рынке оценивается как 0,8 × `unit_value`.

### Числа по умолчанию (`DEFAULTS` в `strategies.ts`)
| Имя | Значение | Смысл |
|---|---|---|
| `restMaxPerDay` | 4 | отдыхов в день на персонажа |
| `restStressShare` | 0,6 | доля максимума `stress`, с которой персонаж отдыхает |
| `restProjectShare` | 0,9 | стресс + вчерашний прирост ≥ этой доли максимума — герой отдыхает утром |
| `failVarShare` | 0,7 | optimizer: доля порога провальной концовки |
| `moneyReserve` | 20 | запас денег |
| `maxHiresDelegator` / `maxHiresOptimizer` | 3 / 2 | наймов за забег |
| `saleTrust` | 0,8 | доля оценки выручки при закупке |
| `randomZeroTimeStreak` | 5 | random: команд без времени подряд |
| `randomSleepWeight` | 0,05 | random: доля снов днём |
| пороги закрытого | 1% / 90% | `strategy_hints.coverage_thresholds` переопределяет: `{ "suspicious": 0.01, "not_hidden": 0.9 }` (также `low`/`high`; числа > 1 читаются как проценты) |
| дни денег | 10, 30, 60, 100, 200 | |

## Исходы (simulator.md §4)
`goal:<заголовок>`, `fail:<заголовок>`, `end:<заголовок>` (концовка без тега), `cap`. «Отказ от победы» — в окне был вариант к `goal`, выбран другой (победа с продолжением); прогон идёт дальше.

## Сводки в `--out`
- `summary.md` — всё ниже в одном файле; строка «без подсказок», если в паке нет `strategy_hints.json`.
- `strategies.csv` — по стратегии: доли цели/провала/потолка, отказа от победы, недееспособности героя (хоть раз за прогон), медиана команд (ок-команд до конца), медианный день конца, медианы денег на дни 10/30/60/100/200 (по дожившим до дня), разброс.
- `outcomes.csv` — по стратегии и исходу: число, доля, медианный день.
- `coverage.csv` — метрика закрытого: вид, id, доля прогонов по стратегиям, всего, пометка (`подозрительно` / `не скрытое`).

**Метрика закрытого.** Перечень: действия с `open_when`, переменные / персонажи / товары с условием `visible`, все модификаторы, все события, все предложения, варианты с `open_when`, все концовки (по `end_game`). Плюс всё, что попало в реестр `opened`, но не в перечень (например, предметы лавки). Считается «открылось/сработало»:
- `debugView().opened` (ключ `var:<владелец>:<id>` сводится к `variable:<id>`, `char:` — к `character:`);
- `fired` — события; `endings_fired` — концовки (по заголовку);
- модификатор — был на любой сущности в контрольной точке; предложение — было в очереди или на доске; вариант — был открыт.

Модификатор, наложенный и снятый между контрольными точками (внутри одного дня), может не попасть в метрику.

**Разброс** — средний коэффициент Жаккара открытых сущностей у пар соседних прогонов (1–2, 3–4, …) одной стратегии.

## Трасса
```
#7 д2 06:00 мон.=24 Усталость=10 | {"type":"market_trip","buy_raw":{"flour":10},"buy_items":[]} | ok
    [good] Пекарь продал «Хлеб» × 16 за 48 мон.
```
Номер команды, день и час до команды, деньги, усталость, команда JSON, итог (`ok`, остановка или код ошибки), строки `Result.events`. В конце — исход, день, число команд и ошибок.

## Скорость
Узкое место — движок (~1 мс на `perform`, CI-029). На этой машине (12 потоков): 1000 прогонов `idle` мини-фикстуры — 6 с; ~1000 прогонов всех шести стратегий (`--runs 167`) — ~100 с, потому что четыре рабочие стратегии на мини-фикстуре не доходят до концовки и идут все 200 дней.
