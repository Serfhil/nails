## 1. Как устроена игра изнутри

- **Время** идёт только от действий. Час — тик. Ночью можно только спать.
- **Всё числовое — переменные.** Деньги, стресс, скорость, опыт навыка, вместимость мастерской. Переменная объявляется один раз и есть у каждой сущности своего типа (персонаж, мастерская, предмет, мир).
- **Всё состояние — модификаторы.** Болезнь, усталость, бонус молота, знание рецепта, «злость Фрола». Модификатор меняет итог переменной или её изменение, живёт по сроку и может быть просто меткой (флагом).
- **Лестница переменной** даёт уровни, звания, ранги, пороги стресса. Ступень несёт модификаторы, пока она текущая.
- **Всё, что тратит время, — действия.** Ковка, учёба, отдых, найм, покупка оборудования. Действие бывает разовым и поручением.
- **Всё, что «случается», — события.** Запускаются сигналом («наступило утро», «истёк модификатор») или условием («денег стало много»). Концовка — тоже событие.
- **Всё, где игрок выбирает, — предложения.** Окно «сейчас» или запись на доске. Вариант может создать обязательство — заказ со сроком.
- **Закрытое не видно.** Пока условие видимости ложно, игрок не знает, что вещь существует.

### 4. Контракт пака

*Этот раздел дословно повторяется в content.md. При расхождении верен core.md.*

#### 4.1 Состав пака
Пак — папка JSON-файлов в UTF-8. Все `id` — латиница `snake_case`, уникальны в пределах типа. Тексты для игрока — по-русски (для этого пака). Ссылки между файлами — только по `id`.

| Файл | Тип | Содержимое |
|---|---|---|
| `pack.json` | объект | метаданные, настройки, старт |
| `variables.json` | массив | переменные |
| `modifiers.json` | массив | шаблоны модификаторов |
| `goods.json` | массив | товары склада |
| `items.json` | массив | типы предметов |
| `workshops.json` | массив | типы мастерских |
| `characters.json` | массив | шаблоны персонажей |
| `actions.json` | массив | действия |
| `categories.json` | массив | необязательно: категории действий для группировки в интерфейсе |
| `events.json` | массив | события |
| `offers.json` | массив | предложения |
| `texts.json` | объект | служебные тексты |
| `strategy_hints.json` | объект | необязательно: подсказки симулятору (simulator.md); движок не читает |

#### 4.2 pack.json
```json
{
  "id": "nails_for_count", "name": "Гвозди для графа", "version": "0.1.0",
  "description": "Деревенский кузнец растёт от гвоздей руками до хозяина мастерской.",
  "names": { "money": "Монеты", "money_short": "мон.", "stress": "Стресс",
             "slots": { "hand": "В руке" },
             "roles": { "hero": "Кузнец", "worker": "Подмастерье", "family": "Семья", "pet": "Питомец" } },
  "settings": {
    "day_start": 6, "day_end": 18,
    "market_hours": 2, "trade_hours": 2,
    "trader_raw_target": { "iron": 10 }, "trade_open_when": null,
    "shop": ["hammer_good"],
    "pools": { "daily": { "chance": 0.5 } },
    "max_event_chain": 32
  },
  "start": { "event": "start_default", "hero": "hero" }
}
```
`name` — человекочитаемое название пака (обязательно), `version` — версия пака строкой, например `"0.2.0"` (обязательно; меняется при каждом заметном обновлении пака), `description` — необязательно: одна-две фразы для игрока о паке (показывается в выборе пака и настройках); `null` или отсутствие — валидно. Все три движок отдаёт в `View.meta` (5.3).

`names.slots` — название для игрока каждого слота персонажа, который встречается в `characters[].slots` или `items[].slot` (обязательно). `names.roles` — подписи ролей персонажей (необязательно; роль без подписи не показывается).

Герой создаётся движком из шаблона `start.hero` до всего остального. Старт — событие (`start.event`), запускаемое сигналом `game_start`. Оно выдаёт деньги, склад, персонажей, мастерскую, модификаторы. Разные старты — разные стартовые события.

#### 4.3 variables.json
```json
{ "id": "stress", "name": "Стресс", "owner": "character",
  "start": 10, "min": 0, "max": 100, "format": "number",
  "visible": { "type": "self_is_hero" },
  "ladder": [
    { "at": 0,   "id": "calm",  "name": "Спокоен",   "modifiers": [] },
    { "at": 75,  "id": "edge",  "name": "На пределе", "modifiers": ["stress_edge"] },
    { "at": 100, "id": "break", "name": "Срыв",      "modifiers": [] }
  ] }
```
| Поле | Обяз. | Смысл |
|---|---|---|
| `owner` | да | `character`, `workshop`, `item`, `world` |
| `start` | да | начальное сырое значение; шаблон сущности может переопределить |
| `min` | да | нижняя граница |
| `max` | | верхняя граница; нет — не ограничено |
| `format` | | `number`, `pct`, `money`; по умолчанию `number`. `pct` хранится долей (0.15 — это 15%). Готовую строку для игрока делает движок (`display` в виде, 5.3): `number` — до 2 знаков после запятой, `pct` — доля × 100 и «%», `money` — число и `names.money_short`; десятичный разделитель — запятая |
| `floor_pct` | | недееспособность, если итог < `сырое × floor_pct/100` |
| `good` | | `up` (больше — лучше, по умолчанию) или `down`; нужен для признака «негативный» и окраски |
| `ladder` | | ступени по возрастанию `at`, у первой `at` = `min` |
| `visible` | | условие видимости (субъект `self` — владелец) |

У каждой сущности типа `owner` есть все переменные этого типа.

**Зарезервированные переменные** (движок их читает; пак обязан объявить все, кроме `money` и `stress`, которые существуют всегда и могут быть объявлены паком, чтобы задать границы, лестницу, видимость):

| id | owner | Что делает движок |
|---|---|---|
| `money` | world | кошелёк; рынок, расходы, найм |
| `stress` | character | показывается у героя в шапке; поведение (пороги, срыв) — пак |
| `speed` | character | скорость действий |
| `defect` | character | шанс брака партии 0..1 |
| `learn_speed` | character | типовой множитель `scale_by` |
| `sell_price` | character | множитель цены продажи |
| `buy_price` | character | множитель цены покупки |
| `commission` | character | доля торговца |
| `wage` | character | жалованье в день (работникам) |
| `hire_cost` | character | цена найма (для `qty_from`) |
| `household_expense` | world | расход дома в день |
| `world_sell_price` | world | мировой множитель продажи |
| `world_buy_price` | world | мировой множитель покупки |
| `max_workers` | workshop | вместимость |
| `equipment_slots` | workshop | слоты оборудования |
| `upkeep` | workshop | содержание в день |

Если пак не объявляет `money` и `stress`, действуют умолчания: `money` — `min` 0, `start` 0, `format: "money"`; `stress` — `min` 0, `max` 100, `start` 0, видна только у героя. Деньги могут уйти ниже нуля только если `min` денег отрицательный. Чтобы ловить банкротство условием «деньги < 0», задайте отрицательный `min`.

#### 4.4 modifiers.json
```json
{ "id": "tasty_dinner", "name": "Вкусный ужин", "text": "Сытый и довольный",
  "var": "stress", "applies_to": "change", "direction": "gain",
  "op": "pct", "value": -20,
  "duration": { "kind": "days", "n": 1 },
  "stack": false, "visible": null, "show_numbers": true, "tags": ["family"] }
```
| Поле | Смысл |
|---|---|
| `var` | на какую переменную действует; нет у флага |
| `target` | для модификаторов от источника (предмет, мастерская, ступень): на кого действует — `owner` (владелец источника, по умолчанию), `hero`, `world`. При наложении эффектом цель задаёт эффект |
| `applies_to` | `value` (итог, по умолчанию) или `change` (изменения) |
| `direction` | для `change`: `gain`, `loss`, `any` (по умолчанию) |
| `op`, `value` | `add`, `pct`, `mult` и величина |
| `value_from` | `{ "var", "subject", "baseline", "per_point" }` — величина из переменной |
| `action_tags` | действует только во время действий с этими тегами |
| `duration` | `{kind:"days",n}`, `{kind:"forever"}`, `{kind:"while",condition}`, `{kind:"source"}` |
| `flag` | `true` — метка без `var`/`op`/`value` |
| `incapacitates` | делает владельца недееспособным |
| `may_be_permanent` | автор сознательно разрешает вечный негатив без снятия |
| `stack` | разрешены копии |
| `on_expire` | эффекты при истечении срока |
| `visible`, `show_numbers` | видимость и показ чисел |
| `tags` | метки для поиска и снятия |
| `data_defaults` | данные по умолчанию |

`duration.kind: "source"` — живёт, пока жив источник (ступень лестницы, предмет в руках, оборудование в мастерской, мастерская). Модификаторы предметов, мастерских и ступеней всегда `source`.

Модификатор **негативный**, если `incapacitates` или он ухудшает переменную (направление «лучше» задаёт `variables[].good`: `up` или `down`, по умолчанию `up`).

#### 4.5 goods.json
```json
{ "id": "iron", "name": "Железо", "unit": "ед.", "price": 2, "buy": true, "sell_default": false, "visible": null }
{ "id": "nails", "name": "Гвозди", "unit": "20 шт.", "price": 3, "buy": false, "sell_default": true }
```
`buy: true` — продаётся на рынке как сырьё. Продать на рынке можно любой товар, у которого стоит галочка.

#### 4.6 items.json
```json
{ "id": "sharpening_stone", "name": "Точильный станок", "kind": "equipment", "price": 80,
  "line": "sharpener", "grade": 1,
  "modifiers": ["can_sharpen"], "vars": {}, "open_when": null,
  "description": "Крутится со скрипом, точит на совесть." }
{ "id": "hammer_father", "name": "Отцовский молот", "kind": "tool", "slot": "hand", "price": 0,
  "modifiers": ["father_hammer_defect"] }
```
- `kind: "tool"` — в слот персонажа (`slot`), модификаторы действуют на владельца.
- `kind: "equipment"` — в слот мастерской, модификаторы — на мастерскую (или на героя и мир, если так указано в поле `target` шаблона). Обязательны `line` (линейка: латиница `snake_case`, не ссылка) и `grade` (целое ≥ 1); правила установки и замены — 3.7.
- Получение предмета создаёт **экземпляр** с собственным `id`. На экземпляр можно повесить модификатор, у него есть переменные с `owner: "item"`.
- Доступ к действию от оборудования делается флагом: оборудование несёт модификатор-флаг на мастерскую, действие проверяет его в `open_when` или `enabled_when`.

#### 4.9 actions.json
```json
{ "id": "forge_nails", "name": "Ковать гвозди", "mode": "both", "hours": 1, "speed_scaled": true,
  "roles": { "actor": { "who": "hero_or_worker", "where": null } },
  "open_when": null,
  "enabled_when": null, "disabled_text": null,
  "cost": [ { "good": "iron", "qty": 1 } ],
  "outputs": [ { "good": "nails", "qty": 10 } ],
  "per_hour": [ { "target": "actor", "var": "smith_xp", "add": 1, "scale_by": "learn_speed" },
                { "target": "actor", "var": "stress", "add": 1 } ],
  "effects": [], "tags": ["craft"], "text": null,
  "description": "Простая работа: железо в гвозди.",
  "category": "forge" }
```
| Поле | Смысл |
|---|---|
| `mode` | `once` (разово), `assignable` (поручение), `both` |
| `roles` | `actor` обязателен; `partner`, `candidate` по желанию. `who`: `hero`, `worker`, `hero_or_worker`, `any`, `pool` (кандидат из пула найма) |
| `open_when` / `enabled_when` | скрыто / неактивно с причиной `disabled_text` |
| `cost`, `outputs` | расход и выход на склад |
| `per_hour` | начисления за час |
| `effects` | после завершения (для назначения — после каждой партии) |
| `tags` | для `action_tags` модификаторов и условий |
| `description` | строка для игрока: пояснение к действию. У каждого действия пака она должна быть, но поле необязательное: `null` или отсутствие — валидно (ни ошибки, ни предупреждения валидатора) |
| `category` | необязательно: `id` из `categories.json` или `null`. Без категории действие валидно и показывается вне групп. Ссылка на несуществующий `id` — ошибка V003 |

Обучение — действие с ролями `actor` и `partner`, `enabled_when` с `var_cmp` (учитель строго выше) и `per_hour` опыта ученику; оба заняты. Найм — действие с ролью `candidate` и эффектом `hire`.

#### 4.9.1 categories.json
Необязательный файл. Порядок записей — порядок групп в интерфейсе.
```json
{ "id": "forge", "name": "Ковка", "view": "select" }
{ "id": "rest", "name": "Отдых", "view": "list" }
```
| Поле | Смысл |
|---|---|
| `id`, `name` | как у остальных сущностей; `name` показывается игроку |
| `view` | необязательно, по умолчанию `list`. `select` — одно действие выбирается из списка, расход и описание выбранного показываются рядом; `list` — раскрывающийся список действий, по умолчанию свёрнут, открыть можно несколько. Движок значение не использует, только отдаёт в вид |

#### 4.12 Условия
Дерево: `{"all":[…]}`, `{"any":[…]}`, `{"not":…}` и листья `{"type":…}`. У любого узла может быть `"text"` — причина для игрока, если узел ложен.

Субъекты: `hero`, `self`, `actor`, `partner`, `candidate`, `participant`, `world`, `workshop` (мастерская субъекта), `char:<id>`.

| type | Поля | Истинно, когда |
|---|---|---|
| `var` | subject, var, op, value; `field`: `value` или `level` | итог (или уровень лестницы) сравнение |
| `var_cmp` | a, b, var, op, `field` | сравнение одной переменной у двух субъектов |
| `has_modifier` | subject, template или tag, `min_count` | есть модификатор (не меньше копий) |
| `has_item` | subject, item | есть экземпляр типа в слоте или инвентаре |
| `stock` | good, op, value | склад |
| `day` / `hour` | op, value | календарь |
| `calc` | name, op, value, `action` | расчётная величина |
| `role` | subject, role | роль персонажа |
| `self_is_hero` | — | субъект — герой |
| `hired` | character | персонаж нанят |
| `worker_count` | op, value | число работников |
| `workshop_type` | subject, workshop | мастерская этого типа |
| `incapacitated` | subject, `permanent` | недееспособен |
| `obligation` | id, state (`active`, `done`, `failed`, `declined`) | состояние обязательства |
| `event_count` | event, op, value | сколько раз сработало событие |
| `some` | among, where | хотя бы один персонаж удовлетворяет |
| `data` | name, op, value | данные события |

Операторы: `>=`, `>`, `<=`, `<`, `==`, `!=`.

| type | Поля | Что делает |
|---|---|---|
| `var` | target, var, `add` или `set` | меняет сырое значение (через модификаторы изменений) |
| `goods` | good, qty | кладёт или забирает со склада |
| `add_modifier` | template, target, `duration`, `data` | накладывает модификатор |
| `remove_modifier` | template или tag, target, `count` | снимает |

| `remove` | what (`item`, `workshop`, `character`), target, `item` | убирает сущность |
| `hire` | target (`candidate` или `char:<id>`) | нанимает |
| `add_to_hire_pool` | character | добавляет в пул |
| `add_character` | character, `as` (`worker`, `family`) | добавляет персонажа без найма |
| `add_workshop` | workshop | новая мастерская |
| `replace_workshop` | target, workshop, `transfer` | апгрейд (3.7; формат `transfer` — там же) |
| `notify` | text, `popup`, `kind` | строка в уведомления; `popup: true` — ещё и окно «Понятно»; `kind` — окраска строки: `info` (по умолчанию), `good`, `warn`, `danger`, `seal` |

Цели: `hero`, `self`, `actor`, `partner`, `candidate`, `participant`, `world`, `workshop`, `all_workers`, `char:<id>`. Любое числовое поле можно заменить на `{"$data": "имя"}`.

#### 4.14 texts.json
Служебные тексты движка с подстановками в фигурных скобках. Обязательные ключи:

`reason_no_time`; `reason_cost` {name, need, have}; `reason_incapacitated` {name}; `reason_night`; `log_batch_done` {worker, item, qty}; `log_batch_defect` {worker, item}; `log_sold` {who, item, qty, money}; `log_bought` {who, item, qty, money}; `log_hired` {name}; `log_expenses` {total}; `log_delivered` {obligation}; `log_declined` {obligation}; `log_failed` {obligation}; `stop_sunset`; `stop_offer`; `summary_title`; `source_sale` {name}; `source_purchase` {name}; `source_wage` {name}; `source_upkeep` {name}; `source_household`; `source_event`; `source_offer`; `source_obligation`; `source_action`; `assign_idle`; `assign_trade`; `reason_invalid`; `reason_not_available`; `reason_offer_pending`; `reason_game_over`; `reason_workers_full` {name}; `reason_trade_not_allowed` {name}; `reason_busy_slot`; `stop_game_over`; `popup_title`; `popup_ok`; `replace_warning` {item, old} (предупреждение о замене оборудования другой линейки, 3.7; `old` — названия кандидатов на замену через запятую, игрок выберет один).

## 3. Как сделать типовые вещи

Все `id` в примерах — **примеры**.

### 3.1 Навык с уровнями
Переменная-опыт с лестницей. Уровень = номер ступени.
```json
{ "id": "smith_xp", "name": "Кузнечное дело", "owner": "character", "start": 0, "min": 0,
  "ladder": [
    { "at": 0,  "id": "l0", "name": "Неумеха",  "modifiers": ["clumsy"] },
    { "at": 10, "id": "l1", "name": "Ученик",   "modifiers": [] },
    { "at": 35, "id": "l2", "name": "Подмастерье", "modifiers": [] } ] }
```
Опыт начисляет действие: `"per_hour": [{ "target": "actor", "var": "smith_xp", "add": 1, "scale_by": "learn_speed" }]`. Условие на уровень: `{ "type": "var", "subject": "actor", "var": "smith_xp", "field": "level", "op": ">=", "value": 2 }`.

### 3.2 Навык, который зависит от другого
Переменная «бронник» объявлена заранее и скрыта (`visible`), пока уровень кузнеца < 5. Действие «учиться броне» скрыто тем же условием (`open_when`). Создавать переменные по ходу игры не нужно и нельзя.

### 3.3 Звание героя, ранг и жалованье работника
Звание — лестница переменной героя (например, опыта или репутации). Ранг работника — лестница его навыка; ступень несёт модификатор `wage` (`op: "add"`). Сургучная печать при смене звания — событие на сигнал `ladder_step` с эффектом `notify` (`popup: true`).

### 3.4 Найм
Персонажи с `hire_pool: true` в пуле. Одно действие на весь пул:
```json
{ "id": "hire", "name": "Нанять", "mode": "once", "hours": 1,
  "roles": { "actor": { "who": "hero" }, "candidate": { "who": "pool" } },
  "cost": [ { "var": "money", "from": "candidate", "qty_from": "hire_cost" } ],
  "effects": [ { "type": "hire", "target": "candidate" } ] }
```

### 3.5 Обучение
```json
{ "id": "teach_smith", "name": "Учить кузнечному делу", "mode": "once", "hours": 4,
  "roles": { "actor": { "who": "worker" }, "partner": { "who": "hero_or_worker" } },
  "enabled_when": { "type": "var_cmp", "a": "partner", "b": "actor", "var": "smith_xp", "field": "level", "op": ">",
                    "text": "Учитель должен быть искуснее ученика" },
  "per_hour": [ { "target": "actor", "var": "smith_xp", "add": 3, "scale_by": "learn_speed" } ] }
```
Последний уровень учитель дать не может (он не выше): его берут самоучкой или событием.

### 3.6 Оборудование открывает действие
Оборудование несёт флаг на мастерскую:
```json
{ "id": "can_sharpen", "name": "Есть точило", "flag": true, "duration": { "kind": "source" }, "visible": false }
```
Действие: `"open_when": { "type": "has_modifier", "subject": "workshop", "template": "can_sharpen" }`. Для мельницы или звёздного титана — то же самое.

### 3.7 Окно выбора с последствиями
Событие с пулом `daily` → эффект `show_offer` → у вариантов модификаторы на `participant` (пример с выходным Фрола — в разделе 4.10–4.11 контракта). Вариант можно скрыть (`open_when`) или сделать серым (`enabled_when`, `cost`).

### 3.8 «Сначала одно, потом другое»: модификатор с таймером
«Выходной сегодня, бодрость завтра»:
```json
{ "id": "day_off", "name": "Выходной", "flag": true, "incapacitates": true,
  "duration": { "kind": "days", "n": 1 },
  "on_expire": [ { "type": "add_modifier", "template": "rested", "target": "self" } ] }
```

### 3.9 Заказ на доске и сюжетный заказ
Доска: `delivery: "board"`, вариант «Взять» с `obligation`. Сюжетный: `delivery: "now"`, варианты «Принять» и «Отказаться». Награда, провал и отказ — `on_done`, `on_fail`, `on_decline`. Одно общее событие провала можно переиспользовать: `on_fail: [{ "type": "run_event", "event": "order_failed", "data": { "penalty": 500 } }]`.

### 3.10 Предупреждение и кража (слушатель)
```json
{ "id": "theft_warning", "trigger": { "conditions": [ { "type": "calc", "name": "wealth", "op": ">", "value": 400 } ] },
  "effects": [ { "type": "notify", "text": "Соседи косятся на вашу кубышку." },
              { "type": "add_modifier", "template": "thief_watching", "target": "world" } ] }
```
`thief_watching` — скрытый модификатор на 2 дня с `on_expire: [{ "type": "run_event", "event": "theft" }]`; событие `theft` проверяет `wealth` ещё раз и забирает деньги и товар эффектами `var` и `goods`. Сейф — оборудование с модификатором-флагом, который событие `theft` проверяет в условии.

### 3.11 «Сырья осталось мало»
```json
{ "id": "low_raw", "stops_time": true, "repeat": { "cooldown_days": 1 },
  "trigger": { "conditions": [ { "type": "calc", "name": "cost_hours", "op": "<", "value": 3 } ] },
  "effects": [ { "type": "notify", "text": "Железа хватит часа на три." } ] }
```
Порог берите не меньше `market_hours`, чтобы игрок успел закупиться.

### 3.12 Срыв и смерть от переутомления
Лестница `stress`: ступень «на пределе» (предупреждение через событие на `ladder_step`), ступень «срыв» — событие накладывает `breakdown` (`incapacitates`, 7 дней) и копию `burnout_scar` (`stack: true`, снимается долгим отдыхом). Смерть — событие по условию `has_modifier` `burnout_scar` с `min_count: 3` и `end_game` с `tag: "fail"`. У каждого поражения должен быть видимый предвестник, иначе валидатор предупредит.

### 3.13 Старость
Событие по условию `day >= N` (плюс любые условия «нет прогрессии») с `end_game`. Постепенное старение — модификаторы по условию дня (`duration: while`).

### 3.14 Победа с продолжением
Событие → `show_offer` с вариантами «Принять место при дворе» (`end_game` с `tag: "goal"`) и «Остаться в кузне» (без эффектов).

### 3.15 Старт
`pack.json → start.event`: событие на `game_start`, выдаёт деньги (`var`), склад (`goods`), мастерскую (`add_workshop`), семью (`add_character` с `as: "family"`), инструмент (`give_item`), модификаторы. Разные старты — разные стартовые события; выбор старта игроком — предложение `now` в стартовом событии.

### 3.16 Сообщить об открытии
Событие на `became_visible` с условием `{ "type": "data", "name": "id", "op": "==", "value": "sharpen" }` и `notify`. Не сообщать — тоже нормально: игрок найдёт сам.

### 3.17 Апгрейд мастерской
Действие с расходом и эффектом `replace_workshop`. Перенос оборудования, работников и модификаторов — автоматический; переопределение — `transfer`.

## 4. Открытые хвосты

Движок умеет, базовый пак не использует. Можно использовать, если это нужно паку:
- **Несколько мастерских.** Эффект `add_workshop`; работников приписывает игрок; переключатель в интерфейсе появляется сам.
- **Цепочки производства.** Выход одного действия — расход другого (полуфабрикаты).
- **Модификаторы на экземпляре предмета.** `add_modifier` с целью-предметом, переменные с `owner: "item"`.

## 5. Чего движок не умеет

Не пытайтесь сымитировать — запишите в `CONTRACT_ISSUES.md`:
журнал воспоминаний, доля чужой работы, масштабирование предмета качеством, случайный выбор k из пула найма, календарь по модулю дня, возраст от дня, управляющий и автопилот, износ как отдельная механика, события посреди дня (вне часовых проверок условий), спрос и насыщение рынка, второй герой, ёмкость склада, формулы в данных, свои расчётные величины, создание переменных по ходу игры.

## 6. Бриф первого пака «Гвозди для графа»

Всё ниже — **замысел и примеры**, не обязательный список. Цель: пак, в который интересно сыграть несколько раз.

**Суть.** Текстовый средневековый инкрементал с тёплым бытовым юмором. Деревенский кузнец с женой, ребёнком, котом и тёщей. Начинает с гвоздей руками, растёт до хозяина мастерской: учит подмастерьев, поручает им работу и торговлю, берёт заказы знати. Играется на телефоне.

**Длина.** Полный забег — 35–40 минут игры.

**Реиграбельность — через скрытый контент.** Метапрогрессии нет. Контента в паке заметно больше, чем видно за один забег. Скрытое открывается решениями игрока, а не только случаем. Игрок должен чувствовать, что сам достиг и выбрал. Ничего не тыкать в лицо: подсказки — у главной линии, скрытые ветки без подсказок.

**Примеры концовок:** смерть героя от переутомления; гибель мастерской (пожар); место при дворе графа (победа, игрок принимает сам, можно продолжить); секретная смерть от старости, если игра затянулась без прогрессии; смерть от стыда (нечем платить). Игрок может проиграть и может избежать поражения разумной игрой. У каждого поражения — видимые предвестники и способ уйти.

**Примеры содержания:** лестница товаров гвозди → подковы → утварь → инструмент → меч; навык кузнеца и скрытые навыки оружейника и бронника; подмастерья с характерами (Ерёмка — быстрый, но портит; Фрол — медленный, но учится и торгует; Тимоха — ровный, позже); стресс героя, отдых, вечер с женой; утренние события семьи (пирог жены, тёща в гостях, кот спрятал молоток); заказы деревни на доске; заказы графа и герцога окнами; кража как наказание за копилку; оборудование, открывающее новые действия; апгрейд кузни в мастерскую.

**Тон.** Тёплый бытовой юмор средневековой деревни. Жена, тёща, сосед и кот — постоянные персонажи.

## 7. Порядок работы и проверка

1. Работа начинается, когда готов валидатор (сообщает оркестратор).
2. Пак пишется блоками (переменные, модификаторы, товары и предметы, персонажи, действия, события, предложения, тексты).
3. После каждого блока — `validate <путь к паку>`. Ошибка — блок переписывается. Не больше трёх попыток на блок; после третьей — запись в отчёт и в `CONTRACT_ISSUES.md`, переход к следующему блоку.
4. Предупреждения валидатора разбираются: исправить или объяснить в отчёте.
5. Чек-лист: в `pack.json` есть `name`, `version` (поднимать при каждом заметном обновлении пака: исправления — третья цифра, новый контент — вторая) и `description` (одна-две фразы для игрока в выборе пака; без него пак валиден, но так быть не должно); все ссылки существуют; у каждого действия есть, кто его делает и когда оно открывается, и есть `description` (короткое пояснение для игрока по-русски; без него пак валиден, но так быть не должно) и `category` из `categories.json` (группа в главной панели: ковка предметов, сброс стресса, работа с подмастерьями, поддержание мастерской и т. п.; без категории действие валидно и показывается вне групп; `view: "select"` — для «выбери, что делать» вроде выбора предмета для ковки, `list` — для раскрывающегося перечня); у каждого товара-сырья есть источник; у каждого обязательства со сроком есть `on_fail`; у каждого `end_game` метка `tag` (`goal` или `fail`); у каждого поражения видимый предвестник; тексты по-русски.
6. Пак лежит в `/packs/nails_for_count/`.
7. В конце — отчёт `reports/content.md`: кратко и сухо — что сделано, что не сделано и почему, открытые вопросы.

Тесты баланса не делаются. Балансировка — на глаз и по ощущению забега.
