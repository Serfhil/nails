# decisions-log.md — история решений

Справочный файл. Если расходится с core.md, верен core.md. Решения ниже приняты владельцем и внесены в core.md 2.1 (копии разделов 4 и 5 — в content.md и view.md; validator.md дополнен, включая CI-015, CI-016).

## 2026-10-27 — правки core.md по итогам первого запуска

1. **Служебные тексты (CI-002).** 12 ключей (`assign_idle`, `assign_trade`, `reason_invalid`, `reason_not_available`, `reason_offer_pending`, `reason_game_over`, `reason_workers_full` {name}, `reason_trade_not_allowed` {name}, `reason_busy_slot`, `stop_game_over`, `popup_title`, `popup_ok`) становятся обязательными в 4.14. Нет ключа — ошибка валидатора.

2. **Цвет уведомления (CI-003).** У эффекта `notify` необязательное поле `kind`: `info` (по умолчанию), `good`, `warn`, `danger`, `seal`.

3. **Перенос при апгрейде (CI-005).** `transfer: { equipment?: boolean, workers?: boolean, modifiers?: boolean, overflow?: "destroy" | "inventory" }`, умолчания `true`, `true`, `true`, `"destroy"`. Переносятся только модификаторы, наложенные эффектами; модификаторы-источники старой мастерской исчезают с ней.

4. **Оборудование (CI-006, CI-020).**
   - Слоты мастерской обезличены: `equipment_slots` — число мест.
   - У оборудования (`items[].kind: "equipment"`) — тип (линейка, например «мехи») и уровень внутри типа.
   - Покупка — действием пака с эффектом `give_item` в мастерскую (в лавку рынка оборудование не кладётся).
   - Движок скрывает такое действие (как ложный `open_when`), если у мастерской 0 слотов или уже стоит оборудование того же типа с уровнем не ниже.
   - Стоит оборудование того же типа ниже уровнем — новое встаёт на его место сразу (прямой апгрейд). Есть пустой слот — встаёт в него.
   - Все слоты заняты оборудованием других типов — игрок получает предупреждение и выбирает, что заменить (вид отдаёт текст предупреждения и варианты, команда `do_action` получает выбранный экземпляр).
   - Заменённое оборудование исчезает. Ручного снятия нет.
   - Неофициальное расширение `equip` с id мастерской убирается; обходной счётчик `slot_used` из пака убирается.
   - Допущение оркестратора (не обсуждалось): если оборудование выдаёт событие или предложение, а свободного слота и прямого апгрейда нет — предмет не выдаётся.

5. **Кандидаты найма (CI-008).** Отдельный список `View.hire_pool` (id, имя, описание, видимые переменные, эффекты). В `characters` — только персонажи в игре.

6. **Названия слотов персонажа (CI-009).** `pack.json → names.slots: { "<slot>": "<название>" }`; в виде `CharacterView.slots[].slot_name`. Валидатор требует название у каждого используемого слота.

7. **Проценты и форматы (CI-010).** В паке доли хранятся долями (`defect` 0..1). Движок отдаёт у каждой переменной вида готовую строку `display` по её `format` («17%», «25 мон.», «0,8»); интерфейс показывает её и сам не форматирует.

8. **Подпись роли (CI-011).** `pack.json → names.roles: { hero, worker, family, pet }`; шаблон персонажа может переопределить полем `role_name`. В виде `CharacterView.role_name` (`null` — не показывать).

9. **Что можно дать персонажу (CI-012).** В виде `CharacterView.equippable` — экземпляры инвентаря, которые этому персонажу можно надеть; считает движок.
